# Что делать сейчас (пошагово)

Ниже — практический план, чтобы восстановить рабочую отправку писем с сайта.

## 1) Домен и доступ

1. Продли подписку Hostinger (если еще не продлил).
2. Обнови данные владельца домена (registrant/domain holder), если они устарели.
3. Заверши подтверждение у регистратора (email/телефон), если он запросит.
4. Проверь, что домен `timepriority.lv` активен и NS-записи указывают туда, где ты реально редактируешь DNS.

## 2) Почтовый ящик

1. Убедись, что ящик `info@timepriority.lv` существует в Hostinger.
2. Зайди в webmail Hostinger и отправь тест на личный email (входящая почта должна работать).

## 3) Resend (исходящая почта)

1. В Resend добавь домен отправки `timepriority.lv`.
2. Скопируй DNS-записи из Resend (SPF/DKIM) и добавь их в активную DNS-зону домена.
3. Дождись верификации в Resend (статус должен стать Verified/green).
4. Сгенерируй/проверь API-ключ Resend.

> Важно: значения SPF/DKIM бери только из панели Resend, не вручную из памяти.

## 4) Render переменные окружения

В Render (сервис API) задай:

- `RESEND_API_KEY` = твой ключ из Resend
- `FROM_EMAIL` = `info@timepriority.lv`
- `BUSINESS_EMAIL` = `info@timepriority.lv` (или другой твой адрес)
- `ALLOWED_ORIGINS` = `https://timepriority.lv,https://www.timepriority.lv`
- `PORT` = `3000`

После изменения переменных сделай Redeploy.

## 5) Проверка API

1. Открой `https://<твой-api-домен>/health` — должен вернуть JSON `{"ok":true}`.
2. Отправь тестовый POST на `/api/subscribe`.
3. В ответе должно быть `ok: true` и `delivery.clientEmailSent: true`.

## 6) Проверка формы сайта

1. Открой страницу подписки.
2. Заполни форму и отправь.
3. Проверь, что письмо пришло на email клиента.
4. Если не пришло — смотри логи Render и статус домена в Resend.

## 7) Если всё еще не работает

Проверь по чеклисту:

- Домен в Resend точно Verified.
- `FROM_EMAIL` соответствует верифицированному домену.
- В Render сохранены актуальные env и сервис перезапущен.
- В `ALLOWED_ORIGINS` включен реальный домен фронтенда.
